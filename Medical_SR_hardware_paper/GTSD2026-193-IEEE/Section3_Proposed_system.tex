\subsection{Overall System Architecture and HW/SW Co-Design Workflow}

Deploying deep super-resolution models on resource-constrained edge modalities presents a fundamental architectural dilemma: general-purpose embedded CPUs lack the parallel compute throughput required for real-time multi-channel 2D convolutions, whereas purely autonomous FPGA implementations suffer from severe development complexity regarding file system I/O, peripheral interfacing, and dynamic memory orchestration. To overcome these constraints, we propose a balanced, end-to-end hardware-software co-design architecture deployed on the Xilinx Zynq-7020 System-on-Chip (SoC). As illustrated in Fig.~\ref{fig:sw_hw_architecture}, the proposed framework is organized into three collaborative computing tiers: (1) a host-level software pre- and post-processing tier, (2) an embedded Processing System (PS) data control and routing tier, and (3) a dedicated Programmable Logic (PL) streaming hardware accelerator.

\centering
\includegraphics[width=\textwidth]{SW-HW_architeture.jpg}
\caption{End-to-end heterogeneous hardware-software co-design architecture across the three computing tiers: (1) Host software/Python environment for image I/O, serialization, and post-processing reconstruction, (2) Zynq PS (ARM Cortex-A9) for memory management and non-blocking AXI DMA transfer coordination, and (3) Zynq PL custom streaming hardware accelerator executing pipelined convolutional inference at 100~MHz.}
\label{fig:sw_hw_architecture}
\end{figure*}

\subsubsection{Host Software Pre- and Post-Processing Tier}
The uppermost software tier, executed within a Python runtime environment, manages high-level clinical image ingestion, data standardization, and final super-resolution image reconstruction. Given an input low-resolution (LR) medical radiograph $I_{LR}$ (e.g., $256 \times 256$ pixels), the software pre-processing pipeline performs dynamic range scaling, extracts structural coordinate patches, and serializes the multi-dimensional image arrays into continuous 1D data streams (formatted as structured text or raw binary buffers). Following hardware acceleration, the software post-processing module receives the raw streaming outputs, deserializes the 1D data stream back into 2D spatial coordinates, reverses dynamic range normalization, and reconstructs the target high-resolution (HR) diagnostic frame $I_{SR}$ (e.g., $1024 \times 1024$ pixels). By offloading non-computational image I/O and format conversions to the host environment, the hardware accelerator remains entirely dedicated to dense arithmetic execution.

\subsubsection{Processing System (PS) Data Control and DMA Routing Tier}
The intermediate tier is hosted on the Zynq Processing System (PS), which incorporates a dual-core ARM Cortex-A9 processor running an embedded Linux kernel with the Xilinx PYNQ runtime environment. The PS acts as the intelligent orchestration bridge between high-level software data structures and the physical hardware logic. To prevent CPU memory-copy bottlenecks during large-volume data transfers, the PS configures and supervises an on-chip AXI Direct Memory Access (AXI DMA) engine connected via 64-bit High-Performance (HP) slave ports.

Memory management is established using physically contiguous buffers allocated in shared off-chip DDR3 DRAM via the `pynq.allocate` memory manager. The PS initiates asynchronous, bidirectional DMA transfers without CPU polling: the transmit channel (\textit{Memory-Mapped to Stream}, MM2S) fetches serialized input image buffers from system DDR memory and injects them directly into the hardware accelerator, while the receive channel (\textit{Stream to Memory-Mapped}, S2MM) concurrently captures the super-resolved output stream and writes it back into destination DRAM buffers. This decoupled DMA streaming architecture ensures maximum memory bandwidth utilization while maintaining near-zero CPU overhead during active inference cycles.

\subsubsection{Programmable Logic (PL) Hardware Acceleration Core}
The bottom tier comprises the custom RTL accelerator instantiated within the Zynq-7020 Programmable Logic (PL), synthesized to operate at a deterministic system clock frequency of 100~MHz. The accelerator datapath conforms to standard AXI4-Stream handshaking protocols to guarantee backpressure-safe, stall-free data ingestion and emission:
\begin{itemize}
    \item \textbf{AXI4-Stream Slave Interface:} Continuously ingests streaming input pixels under `TVALID`/`TREADY` handshaking, routing input activations directly into on-chip 2D line-buffer memory blocks.
    \item \textbf{Pipelined Convolutional Datapath:} Processes intermediate activations sequentially through an initial feature extraction layer (Conv1 paired with parametric non-linear activation), cascaded feature mapping stages (such as multiple residual blocks paired with an element-wise skip connection for residual accumulation), a high-resolution reconstruction stage (spatial upsampling), and a final projection convolution. 
    \item \textbf{Training vs. Deployment Partitioning:} Crucially, while adversarial discriminator networks and perceptual loss models are leveraged off-line during the training phase to guide parameter convergence, only the deterministic forward generator architecture is mapped onto the FPGA fabric for real-time edge clinical deployment, entirely avoiding idle logic consumption.
    \item \textbf{AXI4-Stream Master Interface:} Packs the reconstructed output pixels into continuous stream packets and asserts the `TLAST` sideband signal upon completing the final pixel of each tile, thereby triggering the DMA receive engine to commit the reconstructed data to system memory.
\end{itemize}

The subsequent subsections detail the mathematical formulation of our compact network topology (Section~\ref{sec:topology}), the fixed-point quantization scheme (Section~\ref{sec:quantization}), the boundary-safe overlap-tiling strategy (Section~\ref{sec:tiling}), and the internal microarchitecture of the streaming RTL pipeline (Section~\ref{sec:rtl_arch}).

\subsection{Fixed-Point Mathematical Formulation and Post-Training Quantization (PTQ Q7)}
\label{sec:quantization}
% Outline & Key Concepts:
% 1. Motivation: Complete elimination of floating-point arithmetic units (FPU) to maximize logic density and energy efficiency on Zynq-7020.
% 2. Data Format Definition:
%    - Pixel Activations: Signed S7.0 (1 sign bit, 7 integer bits, 0 fractional bits, range [-128, 127]).
%    - Model Weights: Signed S0.7 (1 sign bit, 0 integer bits, 7 fractional bits, range [-1.0, +0.992]).
% 3. Mathematical Quantization Equations:
\begin{equation}
X^{(0)}(i, j) = \text{clamp}\left(I_{in}(i, j) - 128,\, -128,\, 127\right)
\label{eq:input_quant}
\end{equation}
\begin{equation}
W_q = \text{clamp}\left(\left\lfloor W \cdot 2^7 \right\rceil,\, -128,\, 127\right)
\label{eq:weight_quant}
\end{equation}
\begin{equation}
A_k(i, j) = \sum_{c=0}^{C_{in}-1} \sum_{u=0}^{K-1} \sum_{v=0}^{K-1} X_c(i+u, j+v) \cdot W_{k,c}(u, v) + \left(B_k \ll 7\right)
\label{eq:mac_accumulation}
\end{equation}
\begin{equation}
X_k^{(l)}(i, j) = \min\left(\max\left(0,\, \left\lfloor A_k(i, j) \gg 7 \right\rfloor\right),\, 127\right), \quad l \in \{1, 2\}
\label{eq:layer_activation}
\end{equation}
\begin{equation}
I_{out}(i, j) = \min\left(\max\left(0,\, \left\lfloor A_3(i, j) \gg 7 \right\rfloor + 128\right),\, 255\right)
\label{eq:output_dequant}
\end{equation}
